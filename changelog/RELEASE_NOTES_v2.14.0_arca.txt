RAM 클리너 포팅판 v2.14.0 — 레이드 후 메모리를 붙잡은 모드 이름 찾기

[구분선]

■ 바뀐 것

1) 레이드가 끝났는데도 메모리가 안 풀릴 때, 어느 모드 탓인지 이름을 찾아 줍니다
- 언제: 레이드를 마치고 메인 메뉴로 돌아왔는데도 게임 메모리가 500MB 넘게 남아 있을 때입니다. (F12의 "의심 기준: 레이드 후 남는 메모리" 값, 기본 500MB)
- 전에는: "어떤 모드가 지난 레이드 데이터를 붙잡고 있음"까지만 알려 줘서, 어느 모드인지는 직접 추측해야 했습니다.
- 이제는: 메뉴에서 정리가 끝난 직후, 설치된 모드들이 이미 끝난 레이드의 플레이어·봇·시체를 아직도 들고 있는지 훑어 봅니다. 들고 있는 모드가 있으면 모드 이름과 변수 이름을 로그에 적고, 알림과 F12의 "레이드 후 남은 메모리" 줄에도 모드 이름을 붙여 줍니다.
- 부담: 메뉴에서만 돌고, 메모리가 의심 기준을 넘었을 때만 돌며, 최대 4초에서 멈춥니다. 레이드 중에는 돌지 않습니다.
- 한계: 아무것도 못 찾았다고 그 모드가 무죄라는 뜻은 아닙니다. 더 깊이 숨은 것이나 게임 자체가 들고 있는 것은 못 봅니다.
- 확인: 아직 게임에서 확인하지 못했습니다. 만들어서 빌드만 해 본 상태라, 써 보시고 이상하면 알려 주세요.

2) 기타
- F12 창의 모드 버전과 업데이트 파일 이름이 2.14.0으로 맞춰졌습니다.
- 설명 글(README)의 원작자 표기를 보기 쉽게 나눴습니다. 동작은 바뀐 것이 없습니다.

혹시 레이드 후 메뉴에서 멈춤이 느껴지면 알려 주세요.

■ 설치

RamCleanerInterval-2.14.0-SPT4.1.zip 풀어서 SPT 폴더(예: E:\SPT 4.1)에 덮어쓰기. 설정은 그대로 유지됩니다.

■ 쓰는 법

평소처럼 레이드를 2~3판 한 뒤, BepInEx\RamCleaner\ 폴더의 최신 로그에서 "[leak holders]" 줄을 찾아 보내 주세요.

■ 버그 제보

스크린샷 + BepInEx/LogOutput.log 같이 주시면 빨리 봅니다.

1. 저는 전문 프로그래머가 아니고, AI를 주로 이용하는 바이브코더입니다.

해당말의 뜻은, 저는 매일 구상하고 힘들게 한땀한땀 손으로 모드를 만드는 사람이 아니고

또한, TS/JS (SPT 2.3.1) 시절에 간단하게 모드 수정을 거치며 이 과정이 얼마나 노력을 들이고, 시간이 필요한지 잘 알고 있습니다.

그렇기에, 해당 모드를 수정하면서 아무리 MIT 라이선스를 받았더라도 원 모드 제작자가 소스코드 삭제 및 배포를 중단해달라고 하면 중단할 의향이있습니다.


2. 무단으로 수정한 모드를 "3차 4차 배포하지 마십쇼"

제가 만든 버전이 개선점이 있어도, 오래 사용하지 마세요 저는 "FORGE" 에 올린 것 처럼 바이러스 검사나 디버깅을 완벽하게 수행하지 않습니다.

또한, 제가 포팅한 버전을 "진짜 릴리즈된 버전" 이라고 생각하고, 제 포팅 모드를 들고 원작자에게 가면 얼마나 민폐일까요? 끔찍합니다

저는 모더들을 최대한 존중하는 방향으로 포팅할 계획입니다.

아마, 제가 모드를 제작할 때 하루를 갈아넣어 만들었는데 누군가가 멋대로 코드를 뺏겨 지 멋대로 작성했다면 기분을 썩 좋지않을 것 같습니다.

고로 GITHUB에 README.MD 작성 시, 원작자 표기 및 제가 실제로 제작하지 않은 모드라면 최대한 해당 모드를 제작한 모더의 의견을 존중하는 방향으로 나아갈 것입니다.
