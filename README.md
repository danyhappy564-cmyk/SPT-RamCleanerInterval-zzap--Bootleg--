## 이 모드가 하는 일 (한 줄 요약)

레이드 중에 늘어나기만 하는 게임 메모리를 **끊김이 느껴지지 않는 순간에** 치워 줍니다. GC(관리 메모리), 에셋(텍스처·모델, VRAM),
워킹셋(RAM 비상 정리) 세 가지를 따로 다룹니다.

## 원본 모드가 끊겼던 이유와 메모리가 계속 늘어나는 이유

게임 파일(`Assembly-CSharp.dll`)을 직접 열어서 확인한 내용입니다.

1. **RAM이 12GB 이상인 PC에서는 레이드가 시작될 때 게임이 GC를 완전히 꺼 버립니다.**
   (레이드 준비 단계에서 `GCEnabled = false`. 조건은 게임 설정값 `GigabytesRequiredToDisableGCDuringRaid = 12`)
   - GC가 꺼져 있으면 봇·AI 모드(SAIN 등)·다른 모드가 레이드 동안 만든 임시 데이터가 **하나도 안 치워지고 계속 쌓입니다.**
   - GC를 끈 이유는 GC가 돌 때 생기는 끊김을 피하려는 것입니다. 대신 메모리가 레이드 끝날 때까지 늘어나기만 합니다.
2. **원본 모드의 "RAM 클리너"는 메모리를 비우지 않습니다.** 윈도우의 `EmptyWorkingSet`(게임이 쓰던 메모리를
   RAM에서 대기 메모리/페이지 파일로 밀어내는 기능)을 부를 뿐입니다. 게임이 그 메모리를 다시 쓰는 순간 다시 읽어 와야 해서
   **직후에 끊김이 생깁니다.** 원본은 이걸 5분마다 무조건 했습니다.
3. **(v2.1.0 로그로 확인) 메모리 증가의 대부분은 GC 밖(네이티브)입니다.** 관리 메모리는 GC로 잡히지만, 커밋 메모리는
   1분에 약 1GB씩 계속 늘었습니다. 에셋 정리로 줄어드는지(= 안 쓰는 텍스처·모델) 안 줄어드는지(= 어떤 모드가 붙잡고 있는 누수)를
   v2.1.0 로그의 `UnloadUnusedAssets done ... freed` 값으로 구분할 수 있습니다.

> 참고: GC로 치운 메모리는 게임이 다시 쓰려고 **쥐고 있는 경우가 많아서**, 작업 관리자 숫자가 바로 뚝 떨어지지 않을 수
> 있습니다. F12 "현재 상태"의 "관리 메모리 사용" 수치가 정리 후 내려가는지로 확인하세요.

| 의심 기준: 레이드 후 남는 메모리 (MB) | 500 | 레이드 후 메뉴 GC 뒤 관리 메모리가 레이드 전보다 이만큼 넘게 많으면 경고 |
| 게임 알림으로 표시 | 켬 | 종류별로 레이드당 한 번 |

**읽는 법:**
- "메모리 생성"이 많다고 꼭 누수는 아닙니다. 버려진 메모리는 1번 자동 GC가 치웁니다. **진짜 누수는 ② "GC 뒤에도 남는 양"이 계속 오르는 것**이고,
  그때 생성량 1위 모드가 가장 유력한 후보입니다.
- 화면 제목 줄의 "사망당 ○○MB"가 크면 모드 코드가 아니라 봇 장비 쪽(봇 스폰 모드의 모드 아이템 다양성)입니다.
- 생성량은 게임 환경에 따라 정확한 측정(`per-thread counter`) 또는 근사 측정(`heap size`)으로 잽니다. 어느 쪽인지는 로그 `[mods]` 줄과 F12에 표시됩니다.

## 원인 찾는 법 (추천 순서)

1. 레이드 중 끊기거나 메모리가 계속 늘면 **Ctrl+F9**를 눌러 '집중 분석'이 될 때까지 넘김(게임 알림에 모드 이름이 뜸) → 화면에 원인 추적 패널이 뜸
2. 5~10분 평소처럼 플레이 (봇이 싸우고 죽는 상황이 있어야 표본이 쌓임)
3. 화면의 빨간 "의심" 줄 확인 → **Ctrl+F9**로 다음 모드로 넘기면 원인 추적이 꺼지면서 요약이 전용 로그에 저장됨

5. 판마다 메모리가 계속 쌓이면(세션 보고서의 '레이드 후 남은 메모리'가 매번 +) 모드를 **누수 추적**으로 바꾸고(메인 메뉴에서 Ctrl+F9 또는 F12) 같은 맵 2판 → 로그의 `[leak]`·`[mod objects]` 줄과 세션 보고서를 같이 보내 주세요
6. 여러 판을 비교하고 싶으면 같은 폴더의 **세션 보고서**(`RamCleaner-report-*.html`)를 열어 판별 FPS·메모리 그래프를 보면 됨
7. 끊김 원인에 **"서버 응답 대기 (주소)"**가 자주 나오면 그 주소의 모드가 게임을 멈추고 서버를 기다리는 것 — 해당 모드 쪽 문제

## 다른 최적화 모드와 같이 쓸 때

**CompoundingPerf(zzap)** 는 SPT **서버** 쪽 최적화 모드이고, 이 모드는 **게임** 쪽입니다. 서로를 찾거나 기대지 않아서
**하나만 써도, 둘 다 써도** 그대로 동작합니다.

| | RAM 클리너 (이 모드) | CompoundingPerf |
|---|---|---|
| 정리하는 것 | 게임 프로세스 메모리 | SPT 서버 프로세스 메모리 |
| 레이드 후 정리 | 레이드 끝나고 **20초** 뒤 (`After raid delay`) | 레이드 끝나고 **30초** 뒤 + 서버가 3초 조용할 때 (S16) |
| 설정 | F12 → `RAM 클리너 (RamCleanerInterval)` | F12 → `CompoundingPerf.Client` (서버 모드 필요) |
| 로그 | `BepInEx\RamCleaner\` | `SPT_Runtime\user\logs\CompoundingPerf\` (디버그 로그 켰을 때) |

- **둘 다 쓸 때:** 기본값이면 레이드 후 정리가 약 10초 간격으로 나뉘어 겹치지 않습니다. 이 모드의 대기 시간을 늘렸다면
  CompoundingPerf의 `레이드 끝나고 기다릴 시간`도 그보다 10초 이상 길게 맞춰 주세요.
- 서버가 메모리를 돌려주는 건 이 모드의 정리 **뒤**라서, `After-raid cleanup` 줄의 "시스템 여유" 변화에는 안 들어가고
  그 뒤 15초마다 찍히는 `[mem after raid]` 줄에서 보입니다.
- 이 모드의 "시스템 여유"는 PC 전체 기준이라 서버 메모리도 포함합니다. 시스템 여유가 낮다는 경고가 뜨는데 게임 메모리는 정상이라면,
  화면의 **'SPT 서버'** 칸(14번, v2.11.0부터)에서 서버 메모리를 확인해 보세요. CompoundingPerf 없이도 나옵니다.
- 문제 제보 때 둘 다 쓰고 있다면 두 로그를 같이 보내 주세요. 둘 다 PC 시각으로 찍혀서 시간을 맞춰 볼 수 있습니다.

## 레이드 중 메모리가 계속 늘 때 (조사 결과 요약)

SAIN 시뮬 로그 5개(2026-09-29 ~ 10-01)로 확인한 내용입니다.

1. **관리 메모리(GC)는 이 모드가 잡습니다.** 게임이 레이드 중 꺼 둔 GC를 대신 돌려서 매번 1~1.5GB를 회수합니다.
2. **나머지 증가는 "죽은 봇 수"에 비례합니다.** 시체·떨어진 무기·게임의 모델 보관함(풀)에 남은 장비 모델이 레이드 끝까지 남습니다.
   청소(에셋 정리·워킹셋 정리)로는 줄지 않습니다 — 아직 쓰이는(참조된) 오브젝트이기 때문입니다.
3. **얼마나 크게 늘지는 봇 장비의 다양성이 정합니다.** 모드 무기·부품·장비 종류가 많을수록 봇마다 새 모델·텍스처를 불러옵니다.
   APBS에서 "레이드마다 모드 아이템 일부만" 쓰게 하면 사망 1명당 280~340MB → 60~75MB 수준으로 줄었습니다.
4. 확인 방법: F12 '현재 상태'의 **사망 1명당 메모리**, 또는 로그 `[mem]` 줄의 `per death ...`.
   200MB 이상이 계속되면 봇 스폰 모드의 모드 아이템 설정을 줄여 보세요.

### 로그에서 볼 것 (`E:\SPT 4.1\BepInEx\LogOutput.log`, `RAM 클리너` 줄)

| 줄 | 의미 |
|---|---|
| `[mem] ... per death N MB over M deaths, last 10 deaths K MB` | 사망 1명당 메모리 증가 (위 3번) |
| `GC done ... max slice Nms at frame X/Y` | 자동 GC 결과. 긴 프레임은 마지막 1개(약 50ms)가 정상 |
| `Working set trim ... background call Nms` | RAM 부족 비상 정리. 별도 스레드라 이 시간 동안 게임이 멈추지 않음 |
| `[leak] ...` | 누수 추적을 켰을 때만. 무엇이 늘었는지(종류·이름·위치) |
| `[hitch] 87ms frame ... — cause: SAIN \| mod code in that frame 61ms, top SAIN 55ms` | 끊긴 프레임과 그 원인(모드 / RAM 클리너 / 봇 스폰 / 게임 자체) |
| `[hitch suspect] ...` | 이번 레이드 끊김의 30% 이상을 차지한 원인 |
| `[raid report] ...` | 레이드 결산 한 줄 |

| `[mem suspect] ...` | 메모리 누수 의심 (모드 생성량 / GC 뒤 남는 양 / 사망당 메모리 / 오브젝트 증가) |
| `[fps history] ...` | 같은 맵 이전 레이드와 FPS 비교 + 바뀐 모드 |
| `[mod objects] ...` | 모드별 컴포넌트 증가 (11번을 켰을 때) |
| `[경고] 메모리 한도 임박 ...` / `[경고] VRAM 포화 ...` | 메모리 위험 경고 |
